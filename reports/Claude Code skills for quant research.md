# Vendor four skills, write the fifth yourself

No public Claude Code skill matches the statistical discipline compute-curve already enforces, so the best setup is a small, hand-reviewed set of markdown skills committed under `.claude/skills/`, sitting under a project-specific skill written from the repo's own rules. The ranked shortlist is: **(1) a project-written `compute-curve-research` skill** that encodes pre-registration, `ts_observed` no-look-ahead, Holm/Benjamini-Hochberg, bootstrap CIs, the variants log, the no-fabrication and source-terms rules, and the Alpaca paper-only guard; **(2) Anthropic's `validate-data` and `explore-data`** from the `data` plugin of knowledge-work-plugins (Apache-2.0, prompt-only); **(3) K-Dense's `hypothesis-generation` and `exploratory-data-analysis`** (MIT, local, network-free scripts); **(4) K-Dense's `statsmodels`**, with its arXiv-fetch citation block and version-pinned install lines removed; and **(5) tradermonty's `backtest-expert`** (MIT, no network) as a robustness checklist. DuckDB's official `duckdb-skills` (read-file and query only) and the MotherDuck MCP are worth using interactively for fast Parquet review, but not in autonomous runs. Avoid Alpaca's own `backtest` skill (it bypasses the repo's paper-endpoint guard and can generate an order adapter), K-Dense `database-lookup` (it reads `.env`), TimesFM (non-commercial weights), Firecrawl's skills (global install, proxy escalation, no robots.txt guidance) and the crypto-first trading packs. One mechanical fact decides how all of this gets installed: **cloud sessions load only skills committed under `.claude/skills/`; they ignore marketplace plugins enabled in `.claude/settings.json`**. The repo has no `.claude/` directory today, so every recommendation below is a copy of a reviewed folder, pinned to a recorded commit, plus a `docs/decisions.md` entry (the next free number is D43).

## Only K-Dense carries real statistics, and it targets biomedicine

Three large collections contain substantive statistics content, and only one goes deep. **K-Dense-AI/scientific-agent-skills** (renamed from `claude-scientific-skills`; about **48.2k stars**, 177 skills, MIT at repo level, pushed 2026-10-09) is the one repo every data and finance roundup recommends ([GitHub](https://github.com/K-Dense-AI/scientific-agent-skills)). Snyk's February 2026 "Top 8 Claude Skills for Finance and Quantitative Developers" ranked it first at 8,241 stars ([Snyk](https://snyk.io/articles/top-claude-skills-finance-quantitative-developers/)), and AI Builder Club's data-scientist guide listed it at 34K in mid-2026 ([AI Builder Club](https://www.aibuilderclub.com/blog/claude-code-for-data-scientists-skills-guide)). That growth curve is the strongest usage signal of any statistics repo found, though stars measure the whole 177-skill pack, not any single skill.

The useful K-Dense skills for this repo are prompts with local helper scripts. `statsmodels` covers OLS, GLM, ARIMA/SARIMAX/VAR, **HAC and cluster-robust standard errors**, ADF/KPSS and multiple-comparison correction, and its pitfall list names "using future information" and out-of-sample checks ([SKILL.md](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/statsmodels/SKILL.md)). `statistical-analysis` tells the agent to use **Holm or Benjamini-Hochberg** for test families and to report departures from the plan, but it relies on pingouin, which is outside the core stack ([SKILL.md](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/statistical-analysis/SKILL.md)). `exploratory-data-analysis` ships **"local/network-free"** CLIs (including `missingness_leakage_audit.py`), says to "Label post hoc patterns as exploratory" and to define the FWER/FDR family before confirmatory tests, and says to split by time before fitting ([SKILL.md](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/exploratory-data-analysis/SKILL.md)). `hypothesis-generation` produces **preregistration-ready plans**, has a section on preventing HARKing, and forbids fabricating "data, results, approvals, or preregistration", which mirrors CLAUDE.md's no-fabrication rule almost word for word; its scripts are stdlib-only and local ([SKILL.md](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/hypothesis-generation/SKILL.md)). `statistical-power` adds Monte Carlo power and minimum-detectable-effect calculations at the corrected alpha ([SKILL.md](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/statistical-power/SKILL.md)), and `aeon` warns that random splits leak in time series ([SKILL.md](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/aeon/SKILL.md)).

The catch is the domain. These skills are written for experiments with subjects, APA reporting and GRADE appraisal. **None covers block or stationary bootstrap, the deflated Sharpe ratio, PBO, or HAC lag choice for overlapping returns**, which are exactly the tools a short-history futures relative-value study needs. K-Dense also pins newer libraries (statsmodels 0.15, pandas 3.0, Python 3.12+) than a typical lockfile, so its install lines conflict with `uv.lock`, and the skills are better read as method guidance than followed as install instructions ([SKILL.md](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/statsmodels/SKILL.md)).

Anthropic's own offering is lighter. The `data` plugin in **anthropics/knowledge-work-plugins** (about 28.2k stars, Apache-2.0, pushed 2026-10-09) has a `statistical-analysis` skill with a sensible "When to Be Cautious" section, but its multiple-testing advice stops at **Bonferroni**, with no Holm, BH, stationarity or HAC, so it is weaker than the repo's existing practice ([SKILL.md](https://github.com/anthropics/knowledge-work-plugins/blob/main/data/skills/statistical-analysis/SKILL.md)). Its `validate-data` skill is the more valuable piece: a pre-share QA pass that lists **look-ahead bias, multiple testing and cherry-picked time ranges** among its traps and ends with a "Ready to share / Share with caveats / Needs revision" verdict ([SKILL.md](https://github.com/anthropics/knowledge-work-plugins/blob/main/data/skills/validate-data/SKILL.md)). Both skills already appear in this session's skill list via the claude.ai account, which is an observation of this environment rather than a guarantee for future cloud runs. The headline collections, anthropics/skills (about 180k stars), obra/superpowers (about 297k) and the awesome lists, contain **no statistics skills of their own** ([anthropics/skills](https://github.com/anthropics/skills); [obra/superpowers](https://github.com/obra/superpowers); [VoltAgent](https://github.com/VoltAgent/awesome-agent-skills)).

## Quant skills are practitioner checklists, and the repo already exceeds them

Quant-specific skills exist, but they encode trading hygiene rather than inference. A GitHub code search for SKILL.md files mentioning walk-forward and look-ahead returned 140 files, most of them copies of a single skill, while a search for "deflated sharpe", Benjamini-Hochberg or Newey-West returned **only 4 hits, all in small repos** ([GitHub code search](https://github.com/search?q=filename%3ASKILL.md+walk-forward+look-ahead+backtest&type=code); [GitHub code search](https://github.com/search?q=filename%3ASKILL.md+%22deflated+sharpe%22&type=code)).

The copied skill is **tradermonty/claude-trading-skills `backtest-expert`** (about 3.0k stars, MIT, updated 2026-10-09). It asks for a one-sentence hypothesis, zero-discretion rules, parameter sweeps at 50–150% of baseline, slippage at 1.5–2x, walk-forward out-of-sample results, and "Seek Plateaus, Not Peaks"; it states "No API keys required; No external data dependencies" ([SKILL.md](https://github.com/tradermonty/claude-trading-skills/blob/main/skills/backtest-expert/SKILL.md)). Two weaknesses limit it here. Its bundled `evaluate_backtest.py` scores self-reported summary metrics rather than recomputing anything, and its thresholds (30+ trades, multi-year history) do not fit a compute-futures market with months of data. Other skills in the same repo require FMP, FINVIZ Elite or Alpaca keys, so vendor only this one folder ([README](https://github.com/tradermonty/claude-trading-skills/blob/main/README.md)).

**alpacahq/alpaca-skills `backtest`** (official Alpaca, about 154 stars, Apache-2.0) is the most rigorous about reproducibility: it requires a `notes.md` ledger of every defaulted assumption, fill and fee model, flags same-bar fills as look-ahead risk, and lists anti-patterns such as computing daily Sharpe from per-bar returns ([SKILL.md](https://github.com/alpacahq/alpaca-skills/blob/main/skills/trading-api/backtest/SKILL.md)). It is still a poor fit. It routes through the Alpaca CLI and `alpaca profile login`, forbids direct HTTP calls (the opposite of the repo's guarded `compute_curve.claim4` clients), and offers a "paper forward-validation handoff" that writes `alpaca_order_adapter.py` and `paper_config.json`. Under D30 the only sanctioned path to Alpaca is the repo's own client, which hard-fails unless `APCA_API_BASE_URL` is the paper endpoint; a skill that generates a parallel order path undermines that guard. Read its assumption-ledger idea; do not install it.

The rest are thinner. **wshobson/agents `quantitative-trading`** (about 40.3k stars for the whole marketplace, MIT) names "Pre-registration" as the cure for selection bias but gives no procedure, and its `quant-analyst` subagent is marked "Use PROACTIVELY", so it auto-triggers ([backtesting-frameworks](https://github.com/wshobson/agents/blob/main/plugins/quantitative-trading/skills/backtesting-frameworks/SKILL.md); [quant-analyst.md](https://github.com/wshobson/agents/blob/main/plugins/quantitative-trading/agents/quant-analyst.md)). **agiprolabs/claude-trading-skills** (about 410 stars) has a competent Engle-Granger and Johansen cointegration skill, but it applies a flat p < 0.05 with no multiplicity adjustment, the pack is crypto/DeFi-first with many keyed APIs, and its `LICENSE` file returned 404 ([cointegration SKILL.md](https://github.com/agiprolabs/claude-trading-skills/blob/main/skills/cointegration-analysis/SKILL.md); [README](https://github.com/agiprolabs/claude-trading-skills/blob/main/README.md)). The one skill that targets the repo's actual gap, **Jimmy7892/quant-research-skill**, covers deflated Sharpe, PBO, walk-forward and effective sample size behind a five-phase gated workflow, but it has **7 stars, 0 forks** and bundles four Python scripts written by the author of the backtest engine it promotes ([GitHub](https://github.com/Jimmy7892/quant-research-skill)). Treat it as reading material when writing the project skill, not as an install.

## Data review is well served; data discovery mostly is not

For reviewing data quickly, two official packs cover most needs. Anthropic's `data` plugin adds `explore-data` (nulls, distributions, duplicates, suspicious values) to `validate-data`; it is markdown plus one local zip-packaging script, which makes it the lowest-risk option found ([knowledge-work-plugins data/](https://github.com/anthropics/knowledge-work-plugins/tree/main/data)). The plugin's `.mcp.json`, however, pre-declares HTTP connectors for Snowflake, Databricks, BigQuery, Hex, Amplitude, Atlassian and Definite ([data/.mcp.json](https://raw.githubusercontent.com/anthropics/knowledge-work-plugins/main/data/.mcp.json)), and CLAUDE.md bans MCP connector calls in autonomous runs. Vendoring only the two SKILL.md folders, not the plugin, removes that surface.

**duckdb/duckdb-skills** (official, MIT, v0.2.4, about 600 stars, announced on the DuckDB blog on 2026-09-16) drives the DuckDB CLI to read, profile, query and convert Parquet, CSV and JSON ([DuckDB blog](https://duckdb.org/2026/09/16/duckdb-skills); [plugin.json](https://raw.githubusercontent.com/duckdb/duckdb-skills/main/.claude-plugin/plugin.json)). Its `query` skill asks for confirmation above 1M rows without a LIMIT and sets `allow_persistent_secrets=false`, and `read-file` previews with `LIMIT 20`, which suits the repo's Parquet under `data/raw/` ([query](https://raw.githubusercontent.com/duckdb/duckdb-skills/main/skills/query/SKILL.md); [read-file](https://raw.githubusercontent.com/duckdb/duckdb-skills/main/skills/read-file/SKILL.md)). The rest of the pack carries real risk: `install-duckdb` suggests `curl -fsSL https://install.duckdb.org | sh` and installs community extensions, `duckdb-docs` attaches remote databases from duckdb.org, `read-memories` reads Claude Code session logs, remote reads use `credential_chain` to pick up ambient cloud credentials, and the shared `state.sql` can hold secrets in plain SQL inside the project ([install-duckdb](https://raw.githubusercontent.com/duckdb/duckdb-skills/main/skills/install-duckdb/SKILL.md); [duckdb-docs](https://raw.githubusercontent.com/duckdb/duckdb-skills/main/skills/duckdb-docs/SKILL.md); [README](https://github.com/duckdb/duckdb-skills)). It also needs the DuckDB **CLI binary**, a new dependency that the repo's Python `duckdb` package does not provide. The **MotherDuck MCP** (`motherduckdb/mcp-server-motherduck`, MIT, 527 stars) can open `var/*.duckdb` read-only without taking the lock and caps results at 1,024 rows, but its own README warns that read-only mode "alone is not sufficient" against filesystem access ([README](https://raw.githubusercontent.com/motherduckdb/mcp-server-motherduck/main/README.md)).

Data discovery is mostly MCP territory, and little of it is relevant to GPU rental prices. Hugging Face's official `huggingface-datasets` skill and remote MCP are well maintained ([SKILL.md](https://github.com/huggingface/skills/blob/main/skills/huggingface-datasets/SKILL.md)); FRED and SEC EDGAR have community MCPs under **AGPL-3.0** with client-side rate limiting ([FRED MCP](https://raw.githubusercontent.com/stefanoamorelli/fred-mcp-server/main/README.md); [EDGAR MCP](https://raw.githubusercontent.com/stefanoamorelli/sec-edgar-mcp/main/README.md)); and ondata's CKAN MCP reaches data.gov, but its hosted mode routes queries through a third-party Cloudflare Worker and its local mode runs an unpinned `npx ...@latest` ([README](https://raw.githubusercontent.com/ondata/ckan-mcp-server/main/README.md)). K-Dense's `database-lookup` catalogs 80 APIs, including FRED and EDGAR, and correctly says to rate-limit and treat responses as untrusted, but it tells the agent to "Check only the named key in `.env`", which contradicts CLAUDE.md's "There is no `.env` file" ([SKILL.md](https://github.com/k-dense-ai/scientific-agent-skills/blob/main/skills/database-lookup/SKILL.md)). No maintained, verifiable Zenodo MCP exists (the mcp.so listing points at a placeholder repo), and the official Kaggle MCP's tools could not be confirmed ([mcp.so](https://mcp.so/servers/mcp-zenodo)); the repo's own claim-5 Zenodo downloader is already better. **Firecrawl's skills are the clearest conflict**: `firecrawl-cli init` installs skills "globally to every detected AI coding agent by default", and its proxy tiers include an `enhanced` mode and an `auto` retry that escalates after a basic fetch fails, with no mention of robots.txt or site terms ([firecrawl/cli README](https://raw.githubusercontent.com/firecrawl/cli/main/README.md); [Firecrawl proxies](https://docs.firecrawl.dev/features/proxies)). That escalation path is incompatible with "respect robots.txt and each source's terms" and the cmegroup.com ban. No skill found replaces the repo's robots-aware `http.py` collectors, and none tells the agent to check a source's terms.

## Skill supply chains are attacked, and scanners miss most evasions

Third-party skills run with the agent's permissions, and 2026 produced real incidents. Snyk analysed 3,984 skills from ClawHub and the skills.sh top 100 and found **76 confirmed malicious** skills, 13.4% with a critical issue, and prompt injection in 91% of the malicious ones; the skills.sh top 100 was nearly clean ([Snyk Research](https://research.snyk.io/blog/agent-skills-threat-landscape/)). Koi's ClawHavoc report found 341 malicious skills on ClawHub, rising to **824** within two weeks, most delivering the Atomic Stealer infostealer through fake "Prerequisites" sections ([Koi](https://koi.ai/blog/clawhavoc-341-malicious-clawedbot-skills-found-by-the-bot-they-were-targeting)). ESET's H1 2026 report put directly malicious skills at about **1 in 300** of roughly 900,000 analysed ([Expert Insights](https://expertinsights.com/news/1-in-300-ai-agent-skills-is-directly-malicious-eset-research-finds)), and HKUST's SkillCloak showed that moving a payload into a directory the scanner skips evaded every tested scanner more than 90% of the time ([Help Net Security](https://www.helpnetsecurity.com/2026/07/09/malicious-ai-agent-skills-scan/)). Finance lures such as Polymarket skills and exchange-key stealers recur in these campaigns, which matters for a repo that keeps Alpaca paper credentials in environment variables. No incident was found in Anthropic's own marketplaces.

Even the reputable candidates carry quiet network behaviour. K-Dense's `statsmodels`, `statistical-analysis` and `pymc` each end with a citation block telling the agent to **fetch an arXiv URL** before writing a reference, an outbound call buried in otherwise local skills ([statsmodels SKILL.md](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/statsmodels/SKILL.md)). Its `scientific-critical-thinking` figure path calls OpenRouter, and `timesfm-forecasting` downloads Hugging Face weights whose 3.0 checkpoint is restricted to **non-commercial, non-production use** ([timesfm SKILL.md](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/timesfm-forecasting/SKILL.md)). K-Dense says it scans weekly with Cisco's AI Defense Skill Scanner but "cannot guarantee that every skill has been exhaustively reviewed" as community contributions grow ([README](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/README.md)). Anthropic's own position is blunt: a plugin "can execute arbitrary code on your machine with your user privileges", hooks and MCP servers run outside the sandbox, and with auto-update on "the files you reviewed can change on disk" ([Plugin security](https://code.claude.com/docs/en/plugins/security)). Its engineering post recommends installing skills only from trusted sources and auditing bundled scripts and any instructions to reach external networks ([Anthropic Engineering](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)). One frontmatter field deserves special attention: `allowed-tools` in a committed skill **pre-approves tools even in untrusted folders and `-p` runs**, so vendored skills should drop it ([Skills docs](https://code.claude.com/docs/en/skills)).

Community evidence is thin on quality. The roundups (Snyk, AI Builder Club) rank by popularity, not measured benefit, and one Substack guide warns that most public skills "actively hurt - adding tokens, adding latency" ([corpwaters](https://corpwaters.substack.com/p/the-ultimate-guide-to-claude-code)). Searches aimed at Hacker News, Reddit and X returned no threads, so this report cannot say what those communities recommend.

## Cloud sessions read only committed `.claude/skills/`

The install mechanics settle the method. Claude Code's cloud environment documentation lists the repo's `.claude/skills/`, `.claude/agents/`, `.claude/commands/` and `CLAUDE.md` as carried into cloud sessions, and lists **"Plugins and marketplaces declared in your repo's `.claude/settings.json`" as not carried**: a cloud session "doesn't install the plugins a repository turns on under `enabledPlugins` ... `extraKnownMarketplaces`" ([Cloud environments](https://code.claude.com/docs/en/cloud-environments)). Personal `~/.claude/skills/` does not reach cloud sessions either, and `/plugin` is unavailable there ([Skills docs](https://code.claude.com/docs/en/skills); [Claude Code on the web](https://code.claude.com/docs/en/claude-code-on-the-web)). The docs say skills enabled on claude.ai load into cloud sessions automatically, but a July 2026 user report says they did not in fresh web sessions, so relying on account-level skills for the daily cycle is fragile ([claudeissues #75261](https://claudeissues.com/issue/75261-skills-enabled-on-claude-ai-are-not-loaded-into-claude-code-web-cloud-sessions)). K-Dense's documented install targets (`.agents/skills/`, `npx skills add`) are not Claude Code skill locations, so its folders must be copied into `.claude/skills/` by hand ([GitHub](https://github.com/K-Dense-AI/claude-scientific-skills)).

The procedure that satisfies both the docs and CLAUDE.md is: clone the upstream repo, record the full 40-character commit SHA, read SKILL.md and every reference and script file, strip `allowed-tools`, `` !`cmd` `` injections, network calls and install lines, copy the single folder into `.claude/skills/<name>/`, add a `docs/decisions.md` entry with URL, SHA, licence and reason, and commit. Updates then arrive as reviewed diffs. For anything installed as a plugin locally, pin with `owner/repo#ref` or a `sha` field and leave auto-update off ([Install plugins](https://code.claude.com/docs/en/plugins/install); [Marketplace reference](https://code.claude.com/docs/en/plugins/marketplace-reference)). Settings can harden this further: `Skill(name)` deny rules block a specific skill, `disableSkillShellExecution` turns off injected shell commands, and `allowManagedPermissionRulesOnly` makes Claude Code ignore `allowed-tools` in project skills ([Skills docs](https://code.claude.com/docs/en/skills)).

### The project skill is the highest-value install

The strongest case is for a skill the repo writes itself. The existing evidence shows the repo's tests (`ts_observed` filters, no-look-ahead assertions) and `explore/` machinery (BH screen, one-shot confirmation, shadow forward tests) are already more rigorous than any public skill, and a skill is only a prompt that cannot enforce anything mechanically. What a project skill adds is **recall at the right moment**: a model-invoked checklist that loads when the agent starts an analysis, proposes a hypothesis, or writes a report, and that points at the repo's own sources of truth (`docs/decisions.md`, `docs/variants_log.md`, `docs/exploration_plan.md`, `docs/claim4_plan.md`, `docs/data_sources.md`). It should require labelling every result exploratory or confirmatory, stating the hypothesis family and correction before testing, using block bootstrap and HAC for overlapping horizons, checking a naive baseline out of sample, logging the variant count, saying "too little history" instead of fitting, never generating non-test synthetic data, checking robots.txt and terms before any new source, never touching cmegroup.com, Vast.ai, RunPod or Silicon Data storage, reading secrets only from the environment, and routing all Alpaca traffic through `compute_curve.claim4`'s paper-only guard. It can borrow structure from K-Dense's anti-HARKing section, Alpaca's assumption ledger and Jimmy7892's deflated-Sharpe and PBO phase, with attribution, without importing their code. Because it is written in-house, it needs no supply-chain review, carries no licence question, and loads in every cloud session the moment it is committed.

## Conclusion

The search changes the question from "which skills should we install" to "which few external ideas are worth absorbing into our own skill". Public statistics skills target biomedicine and public quant skills target retail trading; neither encodes the small-sample, multiple-testing, overlapping-horizon inference this repo actually needs, and the one that tries has seven stars. Meanwhile the supply chain is actively hostile, and even the reputable packs hide network calls in citation blocks. The repo's own rules are therefore its most valuable skill content, and vendoring two Anthropic and three K-Dense markdown folders on top adds checklist breadth at low risk.

The cloud-loading rule makes this a governance choice as much as a technical one. Because only committed `.claude/skills/` folders reach cloud and scheduled sessions, every skill the agent can see becomes a reviewed, versioned file under the same commit discipline as `src/`, with a D-entry explaining why it is there. That is stricter than plugin installs and fits the repo's existing culture of recording every assumption. The open questions are empirical: no benchmark shows any of these skills improves analysis quality, so the sensible next step is to add them one at a time and check whether the agent's evaluation reports actually get fewer review findings.
