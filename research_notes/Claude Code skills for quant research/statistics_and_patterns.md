## Which large skill collections contain statistics / data-science / quant skills?

### Takeaway
Only three large collections contain real statistics content: K-Dense-AI/scientific-agent-skills (renamed from claude-scientific-skills; the deepest stats coverage), anthropics/knowledge-work-plugins `data` plugin (lightweight business-analytics stats and an analysis QA checklist), and wshobson/agents `quantitative-trading` plugin (thin backtesting and risk-metric guides). anthropics/skills, obra/superpowers and the awesome lists contain no statistics skills of their own. The lists only link to other repos.

### Inferences
- For the target repo (numpy, pandas, scipy, statsmodels, with Holm/BH, HAC, bootstrap and walk-forward rules), the most substantive general-statistics material is in K-Dense's `statsmodels`, `statistical-analysis`, `exploratory-data-analysis` and `hypothesis-generation` skills. These skills target biomedical and experimental designs: APA reporting, subjects and clusters, GRADE. None of them covers financial-specific inference such as block or stationary bootstrap, the deflated Sharpe ratio, or overlapping-return HAC lag choice.
- The Anthropic `data` plugin is already enabled in this session (`data:statistical-analysis`, `data:validate-data`). Its multiple-testing guidance (Bonferroni only) is weaker than the target repo's existing BH/Holm practice. `validate-data` is still a useful pre-publication checklist.
- K-Dense pins much newer library versions (statsmodels 0.15, NumPy 2.5, pandas 3.0, Python 3.12+) than a typical lockfile. Following its install lines verbatim could conflict with the project's `uv.lock`, so the skills should be used as reading material rather than as install instructions.

## Which skills enforce statistical hygiene (pre-registration, anti-p-hacking, out-of-sample) vs just wrap libraries?

### Takeaway
Hygiene-enforcing: K-Dense `hypothesis-generation` (preregistration, anti-HARKing, no fabrication), K-Dense `exploratory-data-analysis` (label post hoc findings as exploratory, define the FWER/FDR family before confirmation, time-split before fitting), Anthropic `validate-data` (pre-share QA covering look-ahead and cherry-picking), Alpaca `backtest` (assumption ledger, look-ahead warnings) and tradermonty `backtest-expert` (OOS, stress tests). Library wrappers with hygiene footnotes: K-Dense `statsmodels`, `aeon`, `pymc`, `timesfm-forecasting`; wshobson `backtesting-frameworks` and `risk-metrics-calculation`; agiprolabs `cointegration-analysis`.

### Cited Findings
- K-Dense `hypothesis-generation` forbids treating hypotheses as facts and fabricating "data, results, approvals, or preregistration". Its section 10 is "Prevent HARKing and expose deviations", and it ships a preregistration scaffold generator — [SKILL.md](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/hypothesis-generation/SKILL.md)
- K-Dense `exploratory-data-analysis`: "Label post hoc patterns as exploratory. Define the hypothesis family and FWER/FDR procedure before confirmatory tests"; "Do not make causal claims from associations" — [SKILL.md](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/exploratory-data-analysis/SKILL.md)
- K-Dense `statistical-analysis`: Holm or BH for test families, and "Report justified sensitivity analyses and any departures from the plan" — [SKILL.md](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/statistical-analysis/SKILL.md)
- K-Dense `statsmodels` opens with "A successful fit establishes numerical execution; causal identification, calibrated uncertainty and model adequacy require a defensible study design". It is otherwise an API guide — [SKILL.md](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/statsmodels/SKILL.md)
- Anthropic `validate-data` lists "Multiple testing / cherry-picking", "Look-ahead bias" and "Cherry-picked time ranges" — [SKILL.md](https://github.com/anthropics/knowledge-work-plugins/blob/main/data/skills/validate-data/SKILL.md)
- Alpaca `backtest` requires every default and assumption to be logged in `notes.md`, plus a data fingerprint — [SKILL.md](https://github.com/alpacahq/alpaca-skills/blob/main/skills/trading-api/backtest/SKILL.md)
- wshobson `backtesting-frameworks` names "Pre-registration" as the mitigation for selection bias but gives no procedure — [SKILL.md](https://github.com/wshobson/agents/blob/main/plugins/quantitative-trading/skills/backtesting-frameworks/SKILL.md)

### Inferences
- None of the skills enforces anything mechanically: they are prompts. The target repo's tests (no-look-ahead assertions, a `ts_observed` filter) are stronger guarantees than any skill. Skills could at most add a reviewer-style checklist, e.g. `validate-data` or a custom project skill distilled from K-Dense EDA and hypothesis-generation plus the repo's own `docs/decisions.md` rules.
- A project-local `.claude/skills/` skill written by the owner, encoding the repo's own pre-registration, BH, bootstrap and variants-log rules, would likely fit better than any third-party skill.

## Quality and safety concerns (scripts, network calls, prompt injection, licences) and install mechanics

### Takeaway
Most quant and statistics skills bundle Python scripts and pin package versions. Several make network calls: K-Dense's arXiv citation fetch, TimesFM's Hugging Face weights, OpenRouter figures, Alpaca CLI auth, and crypto data APIs. Licences are mostly permissive (MIT, Apache-2.0, BSD-3), but TimesFM 3.0 weights are non-commercial, and some repos have missing or unclear licence files. Install routes are `.claude/skills/<name>/SKILL.md` (project or personal) or plugins via `/plugin marketplace add`.

### Cited Findings
- Claude Code skill locations: Personal `~/.claude/skills/<skill-name>/SKILL.md` (not loaded in Cowork or cloud sessions); Project `.claude/skills/<skill-name>/SKILL.md` ("Commit it so your team gets it too"); Plugin `<plugin>/skills/<skill-name>/SKILL.md`, invoked as `/plugin-name:skill-name`. The folder name `synced` is reserved — [Claude Code docs: Skills](https://code.claude.com/docs/en/skills)

### Inferences
- Fit with the target repo's CLAUDE.md:
  - "Do not call MCP connector tools from autonomous runs" and "Never print, log or commit a secret": the Alpaca skill's CLI auth and the K-Dense OpenRouter, database and arXiv fetches need gating.
  - "Any other dependency needs a recorded reason": pingouin, aeon, pymc and timesfm would each require a `docs/decisions.md` entry.
  - "Never fabricate data": K-Dense's hypothesis-generation explicitly aligns with this.
- Prompt-injection surface: skills load into context with the agent's tool permissions. Registry copies (e.g. byte-identical `backtest-expert` in many registries) could drift or be tampered with. The safest route is to read and pin a specific commit, or to vendor a hand-reviewed markdown-only subset into `.claude/skills/`.
- Lowest-risk, highest-value candidates for this repo (read-only, markdown-first):
  1. Anthropic `data:validate-data`: already installed, no scripts.
  2. K-Dense `hypothesis-generation`: stdlib-only local scripts.
  3. K-Dense `exploratory-data-analysis`: local, network-free CLIs.
  4. K-Dense `statsmodels`: drop the arXiv-fetch citation block and the version-pinned install lines.
  5. tradermonty `backtest-expert`: MIT, no network.
- The quant-trading collections (agiprolabs, the rest of tradermonty) are mostly market-data or broker integrations of little use to a CME compute-futures study.
